# Единая навигация админки: вкладки на URL, журнал под общей шапкой

Дата: 2026-09-03
Версия: 1.0.0

## Проблема

В плагине две несвязанные админ-страницы. `admin.php?page=recrawler` рисует шапку
(лого, название, версия, описание), полосу вкладок и формы настроек.
`admin.php?page=recrawler-log` рисует голый `div.wrap` с таблицей записей — без шапки
и без вкладок. Выглядят как разные плагины.

Дополнительно вскрылись три вещи, которые чинятся тем же заходом:

- Активная вкладка хранится в `localStorage`, URL не меняется. Нет ссылок на вкладку,
  не работает кнопка «Назад», нельзя дать коллеге ссылку на нужный раздел.
- В левом меню только два пункта, хотя разделов девять.
- Переключение вкладок сейчас не перезагружает страницу, поэтому потерять
  несохранённые поля нельзя. После перевода вкладок на ссылки это станет возможно.

## Решение

### 1. Настоящие секции в WPOSA

`add_section()` и `set_sections()` (`src/Views/WPOSA.php:325-345`) пишут в
`$sections_array`, который рендерер не читает — мёртвый код. Оживить:

```php
$wposa->add_section( [ 'id' => 'logs', 'tab' => 'general', 'title' => __( 'Logs', 'recrawler' ) ] );
$wposa->add_field( 'general', [ 'id' => 'enable', 'section' => 'logs', ... ] );
```

В `admin_init()` после цикла по табам добавляется цикл по секциям:
`add_settings_section( $section_id, $title, $cb, $tab_id )` — `page` секции равен id таба.
`do_settings_sections( $tab_id )` (`WPOSA.php:1154`) отрисует их подряд штатно,
рендер менять не нужно.

У поля разъезжаются две вещи, сейчас совпадающие:

- **куда сохраняется** — первый аргумент `add_field()`, он же имя опции;
- **под каким заголовком рисуется** — новый необязательный ключ `'section'`,
  по умолчанию равен табу.

Соответственно в `add_settings_field()` (`WPOSA.php:596`) аргументы `$page` и `$section`
перестают быть одинаковыми.

### 2. Навигация на `?tab=`

`show_navigation()` (`WPOSA.php:1113`) печатает вместо `href="#id"` полный адрес
`admin.php?page=recrawler&tab={id}`; класс `nav-tab-active` проставляется на сервере
по `$_GET['tab']`. `show_forms()` рисует только активную вкладку, по умолчанию первую.

Из `assets/js/admin.js` удаляется блок переключения вкладок (строки 26-76) вместе
с ключом `localStorage`. Переход из вкладки помощи (строки 9-20), который сейчас
программно кликает по соседнему табу, становится обычной ссылкой.

### 3. Все вкладки в левом меню

Каждый таб регистрируется как `add_submenu_page( 'recrawler', $title, $title,
'manage_options', 'recrawler&tab=' . $id )`. Управляется ключом `add_tab()`:
`'show_in_menu' => bool`, по умолчанию `true` — так существующие вызовы в
`Settings.php` не требуют правки, а спрятать отдельную вкладку из меню можно явно.

Две известные шероховатости WordPress:

- подсветку активного пункта ломает слаг с параметром — нужен фильтр `submenu_file`,
  возвращающий `recrawler&tab={$_GET['tab']}`;
- первый пункт подменю WordPress создаёт сам как копию родителя — переименовать
  через `$GLOBALS['submenu']`, иначе он будет называться «ReCrawler», а не «Общее».

### 4. Журнал под общей шапкой

Разметка шапки заинлайнена в `plugin_page()` (`WPOSA.php:1065-1077`). Выносится
в публичный `show_header()` — по образцу уже существующих `show_navigation()`
и `show_forms()`. `plugin_page()` начинает звать три метода вместо двух.

`Main::render_log_page()` (`src/Main.php:331`) зовёт `$this->wposa->show_header()`
и `show_navigation()`, дальше без изменений: своя форма и `$table->display()`.
Инстанс WPOSA уже лежит в `Main::$wposa` (`Main.php:96`).

Страница **остаётся** на `page=recrawler-log`. Это сохраняет её собственный
`screen`, а значит «Настройки экрана», пагинацию и массовое удаление — их код
не трогается вообще. В полосе вкладок и в меню журнал выглядит как остальные разделы.

### 5. Перенос настроек логирования и миграция

Поля логирования (`src/Views/Settings.php:554-621`) переезжают в таб `general`
секцией `logs`. Освободившееся место в полосе вкладок занимает журнал.

Опция `recrawler_logs` сливается в `recrawler_general`. На секцию `general`
переключаются пять мест чтения и определения полей:

- `src/Main.php:371` — `enable`
- `src/Cron.php:67` — `lifetime`
- `src/Cron.php:74` — `cron_events`
- `src/IndexNowAbstract.php:122` — `key_logging`
- `src/Views/Log_List_Table.php:215` — `bulk_actions`
- определения полей в `src/Views/Settings.php`

Миграция вешается в существующий `Main::maybe_upgrade()` (`Main.php:294`) — он уже
сравнивает версию БД с версией плагина на `admin_init`. При совпадении ключей
приоритет у старых значений из `recrawler_logs`; после переноса опция удаляется.

Замечание: `'plural' => 'logs'` в `Log_List_Table.php:40` к опциям отношения не имеет —
это имя CSS-класса `table.logs`, на который завязаны стили уровней
(`assets/css/admin.css:348-362`). Не трогать.

### 6. Предупреждение о несохранённых данных

Один обработчик в `admin.js`: слепок `$('form').serialize()` при загрузке, сравнение
в `beforeunload`, при расхождении — `e.preventDefault()`. Текст диалога стандартный
браузерный: свой современные браузеры игнорируют. Сабмит формы снимает флаг, чтобы
обычное сохранение не вызывало вопрос.

## Что чинится побочно

- `$sections_array` и `hide_admin_notices()` (`WPOSA.php:233`) перестают быть мёртвым кодом.
- Появляются дип-линки на вкладки и работающая кнопка «Назад».

## Проверка

- `composer test` — 148 тестов должны остаться зелёными. `tests/phpunit/bootstrap.php:211`
  стабит `add_submenu_page()` одним возвратом `'recrawler-log'`; стабов понадобится больше,
  так как вызовов станет девять.
- `tests/acceptance/MiscCest.php:15` ходит на `admin.php?page=recrawler`.
- Руками: переход по всем девяти пунктам меню и всем вкладкам; сохранение каждой вкладки;
  подсветка активного пункта меню и активной вкладки; «Настройки экрана», пагинация
  и массовое удаление в журнале; предупреждение при уходе с изменёнными полями;
  обновление с 0.3.4 на сайте с непустой опцией `recrawler_logs`;
  поведение при выключенном логировании (журнала нет ни в меню, ни в полосе вкладок).

## Объём

Девять файлов, существенно затрагиваются четыре: `src/Views/WPOSA.php`,
`src/Views/Settings.php`, `src/Main.php`, `assets/js/admin.js`.
